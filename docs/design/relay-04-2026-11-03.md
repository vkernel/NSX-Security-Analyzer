# Relay option 04 · Application implementation

> **Historical record.** This document describes the design or implementation at the time it was written. Current code, tests and the main documentation take precedence.

Relay **Rail + section panel** is now the shared application layout. An 80 px labeled module rail selects the workspace; a 208 px section panel presents the current module's pages and tasks. The selected Relay logo and the light, dark and system appearances apply across the application.

## Direction

- **Product:** Administrators inspect NSX configuration evidence and coordinate reviewed changes.
- **Character:** Focused, balanced, exact.
- **World:** A control-room routing desk used by engineers, owners and approvers.
- **Moments:** Application relationships and current-versus-proposed naming evidence.
- **Signature:** Relay's continuous route and protected hexagon, with record and environment context alongside decisions.

## Changes

| Area | Behavior |
|---|---|
| Module rail | Short labels and consistent icons; full accessible names and tooltips; staff-only modules remain permission-aware |
| Section panel | Real page destinations, current queues, badges and selected states; snapshot hashes keep the exact retained snapshot |
| Context | Immutable records use their owning environment; aggregate pages identify all environments when no filter is selected |
| Shared navigation | Uses the page's existing navigation anchors, avoiding a second set of route/filter rules; duplicate desktop tab rows are hidden only after enhancement succeeds |
| Mobile | One drawer contains both navigation columns; keyboard focus stays within it, Escape closes it and focus returns to the opener |
| Appearance | System, Light and Dark save only the current user's theme; no reload or replacement of unfinished forms; failed saves restore the prior theme and show a message |
| Shared styling | Bridge 06 white/silver surfaces, steel-blue light actions and mint dark actions, quiet surfaces, consistent heading weights and control geometry |
| Segmentation | Relay colors for allow relationships and application markers; subdued neutral grid; red and amber retain their semantic meanings |
| Branding | Relay mark in navigation and favicons, theme-correct sign-in wordmarks, error pages and fresh standalone reports |

Personal appearance settings, larger text, density, reduced motion and high contrast remain available. Primary button text switches to dark ink on mint in dark mode. Forms, confirmation scopes, permissions and NSX execution safeguards retain their existing behavior. No database migration is required.

Without JavaScript, server-rendered module and section links remain usable and the original page navigation remains visible. On narrow screens, local page tabs remain available while the main drawer is closed. The application uses local font fallbacks rather than requesting external fonts.

## Selected light palette

Bridge 06 replaces the original green-tinted light palette. The module rail stays dark with the mint Relay mark in both modes; the light workspace and section panel use white/silver surfaces with steel-blue controls. See [branding guidance](../branding.md) and the [palette comparison](relay-light-palettes/index.html?palette=bridge). Dark mode retains its palette.

## Validation

- 54 Django tests passed (3 PostgreSQL-only checks skipped in the isolated SQLite fixture), including navigation ownership, permission-aware links, historical snapshot URLs, preference isolation, theme validation/authentication/CSRF, segmentation and VM-pair regressions.
- 103 standalone collector/report tests passed (9 optional-integration checks skipped).
- 47 JavaScript tests passed, including canonical navigation mirroring, unchanged review inputs during theme saving and failure rollback.
- 52 route/viewport/theme combinations returned HTTP 200 with no captured JavaScript page errors or document-level horizontal overflow.
- Real browser checks covered persisted appearance, failed preference saving, inventory/firewall navigation within a retained snapshot, naming queue links, mobile focus trapping and Escape, 320 px larger-text/high-contrast containment, and application evidence drawers.
- Six explicit/System theme combinations confirm Bridge light colors and unchanged dark workspace surfaces under either browser color preference.
- Sign-in was checked in light, dark and mobile layouts: exactly one wordmark is visible, with no document-level horizontal overflow.
- Production manifest static-asset build, JavaScript syntax and `git diff --check` passed.
