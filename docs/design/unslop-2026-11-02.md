# Unslop implementation · 2 November 2026

The redesign applies the current design proposal to shared interface components and the naming, policy-editing, segmentation and deletion-plan workflows. It builds on the existing NSX identity and uses the application's evidence as its visual focus.

## Direction

- **Product:** Network administrators understand collected NSX configuration, review evidence and coordinate controlled changes.
- **Character:** Calm, exact, accountable.
- **World:** A network operations desk with legible records and explicit handovers.
- **Moments:** Application relationships and current-versus-proposed group names.
- **Signature:** Environment, collection time and coverage remain visible alongside decisions.

## Implemented

| Pass | Result |
|---|---|
| Spacing | Consistent shared panel and metric spacing; compact naming filters; selection-only action bar |
| Color | Theme-aware metric surfaces, drawers and segmentation content; quieter name differences |
| Icons | Existing icon system retained; mobile navigation affordance made visible |
| Copy | Short task labels; clear draft/active distinction; readable deletion status and next-reviewer guidance |
| Type | Sentence-case table headings and labels; consistent heading weight and numerical alignment |
| Layout | Contextual naming action drawer; one policy-editing navigation; explicit editor sections; save bar no longer covers components |
| Details | Queue counts, selected-row footer counts, accessible confirmation, mobile empty states, focus and scroll restoration |
| Visuals | Compact unconfigured map; focused application selection; evidence drawer; theme-aware graph and matrix |
| Motion | Existing reduced-motion support retained; no decorative animation introduced |

Naming actions present only the fields for the selected operation. Review dialogs list affected objects grouped by policy; Back retains entered values. Row actions select the intended group. CSV import explicitly uses paths in the file rather than table selection. Validation errors retain selected rows and the submitted action.

Policy components update their summary as they are edited. Fields follow the component source, with formatting and mappings in a disclosure. The example is compact, with a reviewable component breakdown. Saving a draft and activating assessment remain distinct operations.

Deletion-plan summaries update automatically in a read-only region. Exact plans and confirmation forms retain their original scope. Administrators who already approved a cleanup plan receive a clear handover message rather than another approval button. Execution eligibility guidance uses the existing authorization rules. No schema migration is required.

## Validation

- 82 focused Django tests run: 81 passed; one PostgreSQL worker-concurrency test skipped on SQLite.
- 44 JavaScript interaction tests: passed.
- 31 route/viewport combinations across desktop, 390 px mobile, 320 px mobile and dark theme: HTTP 200, no captured JavaScript page errors, no document-level horizontal overflow.
- Real-browser checks: row-specific action, cancelled review retaining draft values, naming assignment through server validation, component edits and nested scope selection, empty state, populated graph with two synthetic relationships, evidence drawer and scroll restoration.
- Synthetic deletion-plan display inspected at all four viewport/theme configurations; authorization and approval behavior covered by the focused tests.
- Actual computed dark metric colors measured at 12.39:1 for the value and 8.34:1 for its label against the surface. This is not a full accessibility certification.
- `git diff --check` passed.

Live NSX writes, production database performance, large production graphs and exhaustive screen-reader coverage were not part of this design validation. Existing approval, permission, live-verification, stale-evidence and no-automatic-retry safeguards remain authoritative.
